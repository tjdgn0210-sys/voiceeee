# M2 계정 · 백업

설계도 18장: "애플 · 구글 · 카카오 로그인, 닉네임, 1기기, 백업 · 복원 · 게스트 기록 선택(불러오기 / 덮어쓰기), 로그아웃, 탈퇴, 초기화 (c)". 담당: 백엔드 + 프론트.

**완료 기준(설계도 18):** **앱 삭제 → 재설치 → 로그인 → 데이터 · 알림 복원 시연**, **다른 기기에서 로그인하면 이전 기기가 정리됨.** RLS 시험(다른 사용자 토큰으로 남의 데이터 조회 · 수정 모두 실패).

선행: M0(Supabase 프로젝트, 개발자 계정, 카카오 앱), M1 완료, 결정 D-1(닉네임 문자) · D-5((c) 범위) · D-6(교체된 기기 처리) · D-16(로그아웃 시 푸시 토큰 · 기기 삭제).

## 서버 단위 (B = 백엔드 담당)

### B2-01 프로젝트 골격 · 인증 제공자 (설계도 3.1, 13.8)
- `supabase/` 폴더(M0-02), 마이그레이션은 시간순 번호. 모든 테이블 RLS 켬, **기본은 모두 거부**.
- 인증 제공자: 애플 · 구글 · 카카오. 이메일 · 전화번호 로그인 없음. 카카오는 닉네임 · 고유 ID만 요청(이메일 수집 없음). 구현 방식은 M0-02에서 확인한 결과를 따른다.
- 완료 기준: 세 제공자로 로그인해 `auth.users` 행이 생김(개발 빌드에서 확인).

### B2-02 profiles · nickname_holds · active_devices (설계도 13.1)
- 테이블 DDL은 설계도 13.1을 따른다(제약 · RLS 의미 유지). **D-1에 따라 닉네임 정규식은 `^[가-힣A-Za-z0-9_]+$` 권장**(확정 전에는 구현 보류).
- 함수(보안 정의자, 로그아웃용 `unregister_device` 포함 — D-16): `create_profile`(**최초 가입 때 한 번**: 닉네임 + 기본 공개값 + `age_confirmed_at` + `terms_version`을 NOT NULL 제약에 맞춰 **한 트랜잭션으로** `profiles` 행을 만들고, 이후 M3에서 만드는 `trials` 행도 같은 시점에 만들도록 확장 지점을 둔다), `check_nickname`(가능 여부 + 사유: 형식 · 중복 · 금칙어 · 보류 중 · 30일 제한), `set_nickname`(30일 1회 제한 · 금칙어 · `nickname_holds` 확인 · 이전 닉네임 30일 보류 등록을 **한 트랜잭션**), `update_profile_settings`(공개 기본값, `audience_mode`, `searchable`, 알림 전체 · 잠금 화면 제목, 기본 알림 오프셋), `register_device`.
- 금칙어 목록은 서버 테이블로 두고 운영자가 관리(욕설 · "관리자" · "운영자" · 앱 이름). 영문 대소문자는 같은 것으로 본다(`citext`).
- `register_device`: `active_devices`를 새 기기로 교체하고 이전 기기의 세션을 무효화. **응답에 이전 기기의 마지막 백업 시각(`previous_last_backup_at`, 없으면 null)을 포함**한다(F2-07 안내 문구에 필요). 이후 **모든 보호된 함수**는 요청의 `device_id`가 활성 기기와 다르면 `409 DEVICE_REPLACED`.
- 완료 기준: 함수별 시험 + RLS 시험(남의 `profiles`/`active_devices` 수정 불가).

### B2-03 backup_records · backup_upsert · backup_list · backup_delete_all (설계도 13.5)
- `entity_type`: EVENT, TRANSACTION, TASK, REMINDER, SETTING, RECEIVED_COPY, INBOX, TOMBSTONE(받은 항목 관련 3종은 M4에서 채워지지만 CHECK 목록에는 지금 포함).
- 쓰기는 `backup_upsert`(직접 쓰기 정책 없음). 함수는 **활성 기기 · 세션을 검사**해 교체된 이전 기기가 새 기기 백업을 덮어쓰지 못하게 한다. 들어온 `updated_at`이 저장된 값보다 오래되면 무시. 최대 500건 묶음, `backup_list`는 페이지 단위.
- `backup_delete_all(scope)`은 초기화 (c)와 O6 [이 폰 기록으로 덮어쓰기]가 함께 쓴다(`scope = 'PERSONAL'`만 정의: 아래 D-5 권장 범위). **범위는 D-5 확정 전까지 구현 보류**(설계도 3.7 문구는 "내 백업 전체"이지만 받은 항목 사본 · 삭제 기록까지 지우면 재설치 시 불일치 · 되살아남 위험). D-5 권장안: 개인 기록(EVENT · TRANSACTION · TASK · REMINDER · SETTING)과 공개 일정 사본만 삭제하고 RECEIVED_COPY · INBOX · TOMBSTONE은 유지. `public_events`는 M4(B4-05)에서 생기므로 **M4 B4-07에서 이 함수를 확장해 공개 일정 사본 삭제를 더한다.**
- 완료 기준: 중복 업로드 멱등, 오래된 `updated_at` 무시, 다른 사용자/교체된 기기의 쓰기 거부 시험.

### B2-04 delete_account (설계도 3.7)
- 즉시 삭제: 계정 · 친구 관계 · 보낸 항목 원본 · 백업 · 프로필 사진 · 닉네임(닉네임 문자열은 `nickname_holds`에 30일 예약). 친구들에게 `FRIEND_ACCOUNT_DELETED` 변경 기록(M4에서 `change_log`와 연결), 대기 전달 취소, auth 사용자 삭제(연쇄 삭제). 응답에 "스토어 구독은 해지되지 않아요" 문구를 포함.
- M2 시점에는 친구 · 공유 테이블이 아직 없으므로 **있는 테이블까지만** 처리하고, M4에서 확장하는 지점을 코드 주석이 아니라 M4 문서의 B4-07에 적어 둔다.
- 완료 기준: 탈퇴 후 해당 사용자 데이터가 어떤 테이블에도 남지 않음(닉네임 보류 제외) 시험.

## 앱 단위 (F = Claude Code)

### F2-01 Supabase 클라이언트 어댑터 · 세션 (설계도 2.3, 12.1)
- 설치: `@supabase/supabase-js` + 세션 저장용 보안 저장소(`expo-secure-store`) — 설치 시 `npx expo install`, 이름 · 사유 보고. URL · anon 키는 환경 변수(`EXPO_PUBLIC_*`), **서비스 키는 앱에 넣지 않는다**(16.2).
- 위치: `adapters/supabase/`. 인터페이스는 `application/` 쪽(예: `AccountGateway`)에 두고 구현은 어댑터에 — 시험에서는 가짜 구현으로 바꾼다.
- 자동 로그인(세션 유지). 모든 서버 호출에 `device_id`(설치 시 생성해 보안 저장소에 보관)를 포함하고, `409 DEVICE_REPLACED`는 한 곳(공통 호출기)에서 처리.
- 계정 상태 모델: `GUEST | SIGNED_IN(profile)`. 시안의 `session`, `account` 상태를 참조.

### F2-02 로그인 선택(O3) · 약관 · 만 14세 동의 (설계도 3.1, 3.7, 11.2 O3)
- 버튼: [애플로 계속] [구글로 계속] [카카오로 계속] [로그인 없이 시작]. 약관 · 개인정보 처리방침 링크, **"만 14세 이상입니다" 확인을 함께 받음**(동의 전에는 로그인 버튼 비활성). 도움말: "애플과 구글 계정은 서로 다른 계정이에요. 플랫폼을 바꾸면 백업과 구독이 이어지지 않아요."
- 구현: 애플은 네이티브 로그인(`expo-apple-authentication`), 구글 · 카카오는 방식 선택(네이티브 SDK 또는 `expo-web-browser` OAuth, 이미 설치됨) — **선택 기준: M0-02에서 확인한 Supabase 제공자 지원 방식을 따르고, 결정은 앱 소유자가 `docs/impl/m2-decisions.md`에 기록한다.** **개발 빌드(EAS) 필요** — Expo Go에서는 동작하지 않음을 보고에 명시.
- 로그인 필요 기능(AI · 친구 · 구독)을 게스트가 누르면 같은 화면(또는 시트)으로 이유 문구와 함께 안내(시안 `LOGIN_PROMPTS`).
- 실패 처리: 취소 · 네트워크 오류 · 제공자 오류를 구분해 한국어 문구로 표시.

### F2-03 닉네임(O4) · 기본 공개(O5) (설계도 3.4, 3.1, 11.2)
- O4: 입력창 + **실시간 규칙 · 중복 검사 결과**(디바운스 후 `check_nickname`), 사유는 입력창 아래 표시(형식 · 중복 · 금칙어 · 보류 · "다음 변경 가능일"). [다음]은 통과해야 활성.
- O5: [공개] [비공개] 설명 카드. 선택값은 **로그인 이후 새로 만드는 항목에만** 적용, 과거 항목을 한꺼번에 공개하지 않음(3.3). 게스트 때 만든 항목은 모두 비공개로 남는다.
- 이미 프로필이 있는 계정(재설치 · 기기 변경)은 O4 · O5를 건너뛴다.
- 가입 연령 확인 시각 · 약관 버전은 닉네임 · 기본 공개값과 함께 `create_profile` 한 번으로 `profiles.age_confirmed_at`, `terms_version`에 기록(13.1). O4 · O5 입력은 앱에서 모았다가 O5 완료 때 한 번에 보낸다(중간에 그만두면 프로필이 생기지 않는다).

### F2-04 outbox · sync_state 마이그레이션 004 · 백업 업로더 (설계도 12.3 · 12.4 · 3.6)
- 마이그레이션 `004-outbox-sync.ts`: `outbox(id, kind, entity_type, entity_id, payload_json, created_at, attempts, last_error, state)`, `sync_state(key, value)`(마지막 백업 시각, 활성 기기 id, 복원 커서 등).
- 엔터티가 바뀔 때마다(저장소 계층 경유, UI 아님) outbox에 쌓는다. 온라인이면 최대 수 초 묶음으로 업로드, 오프라인이면 연결 복귀 후 업로드(네트워크 상태 감지 + 앱 포그라운드 전환).
- **요청마다 `clientRequestId`(UUID)를 붙여 서버가 중복을 무시**(멱등). 실패 시 지수 백오프 1s · 2s · 4s … 최대 5분, **5회 이상 실패하면 설정 > 내 데이터에 오류 표시**(실패를 숨기지 않음).
- 백업 대상: 지출 · 수입, 일정, 할 일, 리마인더, 앱 설정(글자 크기 · 알림 · 보내기 기본값 · 공개 기본값). **받은 항목 사본 · 수신함 · 삭제 기록(`RECEIVED_COPY` · `INBOX` · `TOMBSTONE`)의 업로드 · 복원은 M4 F4-02b가 맡는다**(그 전에는 대상이 없다). **제외:** `rawInput`(백업 시 null), ActionLog, 대화 맥락, 임시 초안, 오디오. 그래서 복원 후에는 되돌리기 기록이 없다.
- 충돌 규칙: 엔터티별 `updated_at`이 더 최근인 쪽(1계정 1기기이므로 단순).
- 설정 > 내 데이터: "마지막 백업 시각", "백업 대기 중 N건", 실패 표시.
- 시험: 오프라인에서 쌓인 변경이 복귀 후 순서대로 전송, 같은 요청 재전송 시 중복 없음, 5회 실패 시 오류 표시, `rawInput`이 페이로드에 없음.

### F2-05 백업 선택(O6) · 복원 중(O7) (설계도 3.3 · 3.6, 시안 `#onboardPage` 백업 선택 · 복원)
- 로그인 직후 서버 백업 존재 확인:
  - 서버 백업 없음 + 폰에 게스트 기록 있음 → 폰 기록을 그대로 그 계정 데이터로 삼아 **전체 업로드**.
  - 서버 백업 있음 + 폰에 게스트 기록 없음 → 복원.
  - **둘 다 있음 → O6 선택 화면:** [서버 백업 불러오기](폰의 게스트 기록을 지우고 복원) / [이 폰 기록으로 덮어쓰기](서버 백업을 지우고 폰 기록을 올림). **양쪽 기록 건수**와 "되돌릴 수 없어요" 문구를 표시. 병합은 1차에 없음.
- O7 복원 중: 진행률 표시 → 로컬 DB에 기록(**저장소 계층 경유**, ActionLog에는 "동기화" 출처) → **앞으로 남은 알림 전부 재예약**(M1-08 어댑터, 64개 한도 규칙 적용) → 완료. 실패 시 [다시 시도] + 실패 건수.
- **복원 중 앱 종료:** 페이지 커서를 `sync_state`에 저장해 다음 실행 때 이어서 복원(15).
- 복원 후 알림 · 마이크 권한은 설치마다 새로 받아야 하므로 3.2의 권한 흐름(M1-10)을 다시 거친다.
- 시험: 서버 백업 × 폰 게스트 기록 네 가지 조합 중 동작이 있는 세 가지(없음·없음은 동작 없음), 복원 중단 후 재개, 복원된 데이터의 `rawInput = null`.

### F2-06 게스트 → 로그인 전환 안내 (설계도 3.3)
- 게스트가 기록을 **3건 이상 저장하면 "로그인하면 백업돼요" 안내를 한 번**(닫으면 다시 띄우지 않음, 홈 배너는 유지). 저장 건수는 지출 · 일정 · 할 일 저장 시 센다(수정은 세지 않음).
- AI가 필요한 문장 · 친구 기능을 누르면 같은 방식으로 로그인 안내(문구는 시안 `LOGIN_PROMPTS`).

### F2-07 1계정 1기기 (설계도 3.5, 13.1)
- 로그인 직후 `register_device`. 새 기기 로그인 직후 안내: "이전 기기의 마지막 백업: 10월 2일 15:30(`register_device` 응답의 `previous_last_backup_at`). 그 이후 이전 기기에서 바꾼 내용은 옮겨지지 않을 수 있어요." 후 복원(시안 `#deviceSheet`).
- 이전 기기가 서버 통신 중 `DEVICE_REPLACED`를 받으면 "다른 기기에서 로그인했어요" 안내 → 로컬 데이터 삭제 → 게스트 첫 화면(D-6: 경고 없이 정리).
- 시험: `DEVICE_REPLACED`를 가짜 서버가 돌려줄 때 로컬 DB가 비워지고 첫 화면으로 이동. **실기기:** 두 기기로 실제 확인.

### F2-08 로그아웃 · 탈퇴 · 초기화 (c) (설계도 3.7, 11.2 T7, 시안 `#logoutSheet`, `#dangerSheet`)
- 로그아웃: 로컬 데이터 삭제 + **서버의 `active_devices` 행 · `push_token` 삭제**(D-16 권장, 백업은 유지). **백업되지 않은 변경이 있으면** 먼저 업로드를 시도하고, 실패하면 "N건이 아직 백업되지 않았어요. 그래도 로그아웃할까요?"(15). 오프라인이면 같은 경고 + 연결이 없어 백업할 수 없다는 사유.
- 탈퇴: **2단계 확인**(1단계 "무엇이 지워지는지" 목록, 2단계 "탈퇴" 단어 입력 또는 길게 누르기). 화면에 "구독은 앱에서 해지되지 않아요. 앱스토어 / 플레이스토어 구독 관리에서 해지하세요." + 이동 버튼(스토어 구독 관리 URL 열기). 오프라인이면 버튼 비활성 + "인터넷 연결이 필요해요". 성공하면 앱 데이터 삭제 후 첫 화면. 재가입은 새 계정(체험 3회 · 공유 체험 1회 다시 지급).
- 초기화 (c): 로그인 사용자는 서버 `backup_delete_all`(범위는 D-5 확정 후) + 폰의 개인 기록 삭제. 게스트는 폰 데이터만. 2단계 확인. 초기화 (a)(b)는 M4.
- 시험: 미백업 건수 경고 3가지(정상 · 실패 · 오프라인), 탈퇴 2단계, 오프라인 비활성.

### F2-09 내 프로필 · 설정 계정 구역 (T1, 설계도 10.1 · 3.4)
- 내 프로필: 닉네임 표시와 변경(30일에 1회, **다음 변경 가능일 표시**, 사유 표시), "닉네임으로 나를 찾을 수 있게 하기" 토글(기본 켜짐).
- 계정: 로그인 수단 표시, 로그아웃, 탈퇴. 사진은 M4.
- **서버 설정 동기화:** 공개 기본값 · `searchable` · 알림 전체 · 잠금 화면 제목 · 기본 알림 오프셋 · (M4에서) `audience_mode`는 바뀔 때마다 `update_profile_settings`로 서버에 저장하고, **로그인 직후와 M4 진입 시 1회 전체 업로드**한다(M4 대체 알림이 서버의 `default_reminder_offset`을 쓰기 때문).
