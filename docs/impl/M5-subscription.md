# M5 구독

설계도 18장: "상품 등록, 구매 · 검증 · 웹훅 · 복원, 페이월, 만료 처리". 담당: 백엔드 + 프론트.

**완료 기준(설계도 18):** **샌드박스 구매 · 갱신 · 해지 · 환불 · 복원 시나리오 통과.**

선행: M2(계정) · M3(`entitlements` · `usage_counters` 뼈대) · M4(보내기 한도가 구독 상태를 본다). Apple Developer Program · Google Play Console 가입과 구독 상품 등록(앱 소유자). **개발 빌드(EAS) 필수** — Expo Go에서는 결제를 시험할 수 없다.

## 제품 규칙 요약 (설계도 9장, 1.3)

| 플랜 | 가격(월, 부가세 포함) | AI | 보내기 |
| --- | --- | --- | --- |
| 무료 회원 | 0원 | 체험 3회(평생) | 체험 1회(평생, 일정만, 수신자 1명) |
| 기본 | 2,900원 | 월 150회 · 하루 20회 | 하루 50건 |
| 플러스 | 7,900원 | 월 500회 · 하루 40회 | 하루 50건 |

- **"무제한"이라는 이름 · 표현은 어디에도 쓰지 않는다**(앱 · 스토어 설명 · 페이월). 한도는 숫자로 표기한다.
- 월 한도는 **구독 결제 주기(구매일 기준 1개월)** 마다, 하루 한도는 **KST 자정**에 초기화.
- 기본 → 플러스 **업그레이드**: 이번 주기 사용량은 이어지고 한도만 커진다(예: 120회 사용 → 남은 380회). 업그레이드로 스토어 결제 주기가 새로 시작되면 서버가 **직전 월 bucket의 사용량을 새 bucket으로 이전**(bucket 키 = 스토어가 알려 준 `period_start`). **이전은 업그레이드에만 적용한다.** 같은 플랜의 정기 갱신은 새 bucket이 0에서 시작하고, 다운그레이드(플러스 → 기본)는 다음 갱신 시점에 바뀌므로 이전하지 않는다. (설계도 9장이 업그레이드 외의 이전을 정하지 않아 위와 같이 둔다.)
- 구독 중에는 체험 횟수를 쓰지 않고 **보존**, 만료 후 남아 있으면 다시 쓴다.
- 연간 결제 · 스토어 무료 체험 기간 상품은 **1차에 두지 않는다**(구조상 막지는 않음).
- 만료되면: 새로 보내기 · 지출 보내기 · AI(체험 외)가 막힌다. 이미 보낸 항목의 수정 · 취소, 받은 항목, 친구, 수신 설정, 백업은 그대로. **결제 실패 유예 기간에는 구독 혜택을 유지**한다(9.3).
- 외부 결제 링크를 앱에 두지 않는다(디지털 구독은 스토어 인앱결제만, 9.4).

## 서버 단위 (B)

### B5-01 결제 검증 방식 결정 (설계도 13.9) — 백엔드 담당
| 방식 | 장점 | 단점 |
| --- | --- | --- |
| 직접 구현 | 외부 비용 없음, 데이터 직접 보유 | 애플 · 구글 검증 API, 서버 알림, 유예 · 환불 처리를 모두 구현 |
| RevenueCat 등 | Expo 연동 예제 많음, 복원 · 웹훅 단순 | 매출 규모별 비용(**확인 필요**), 외부 의존 |
- 어느 쪽이든 **`entitlements` 테이블이 최종 기준**이고 앱은 서버 값으로만 기능을 연다(9.4). 결정과 사유를 `docs/impl/m5-decisions.md`에 기록하고, 선택에 따라 앱 단위 F5-01의 라이브러리가 정해진다.

### B5-02 entitlements · get_entitlement · iap_verify (설계도 13.6 · 13.7 · 9.4)
- `entitlements(user_id, plan FREE|BASIC|PLUS, platform, product_id, original_transaction_id UNIQUE, period_start, period_end, status ACTIVE|GRACE|EXPIRED|REVOKED)`.
- `iap_verify(platform, 영수증)`: 앱이 보낸 영수증(구글 `purchaseToken`, 애플 서명된 거래 정보)을 **서버가 스토어에 검증한 결과로만** 권한을 부여. 앱의 판단만으로 기능을 열지 않는다.
- `get_entitlement` → `{ plan, 한도, 사용량, 체험 남은 수, 주기 종료일 }`. 앱은 표시용으로만 캐시.
- **다른 계정에 이미 붙은 구매**(`original_transaction_id` 중복)이면 오류 `IN_USE_BY_OTHER` → 앱 문구 "다른 계정에서 사용 중인 구독이에요"(9.4).
- 업그레이드(기본 → 플러스) 시에만 bucket 사용량 이전(위 규칙). 완료 기준: 120회 사용 후 업그레이드하면 남은 380회, 같은 플랜 갱신은 0에서 시작, 다운그레이드는 이전 없음 시험.

### B5-03 웹훅 · 갱신 · 해지 · 환불 · 유예 (설계도 9.4, 16.2)
- `iap_webhook_apple`(App Store Server Notifications v2, **JWS 서명 검증**), `iap_webhook_google`(Real-time Developer Notifications, **Pub/Sub 인증 검증**). **멱등**: 알림 id를 저장해 같은 알림을 두 번 처리해도 결과가 같다.
- 반영: 갱신(`period_*` 갱신), 해지(기간 끝까지 `ACTIVE` 유지 후 `EXPIRED`), 환불(`REVOKED`), 결제 실패 유예(`GRACE` — 혜택 유지), 만료. 변경 시 `change_log`에 `PLAN_CHANGED` 기록 → 다음 `sync`에서 앱이 반영.
- 서명이 틀린 요청은 거부(상태 변경 없음). 로그에는 거래 식별자만 남기고 개인정보는 남기지 않는다.
- **확인 필요:** 구독 거래 정보의 법정 보관 기간(16.1), 환불 · 부분 환불 정책, 소규모 사업자 프로그램 수수료(15% 가정 · 미가입 시 30%).

### B5-04 서버 쪽 게이트 (설계도 9.3 · 13.7)
- `send_item`의 구독 검사(`NOT_ENTITLED`), AI 차감, 체험 규칙이 **`entitlements.status`** 를 따른다: `ACTIVE` · `GRACE` = 구독자, `EXPIRED` · `REVOKED` = 무료 회원(체험 남아 있으면 사용 가능). `update_item` · `cancel_item`은 만료돼도 허용.
- 시스템 알림(선택): 구독 만료 예정 3일 전(8.1).
- **개발용 플래그 제거:** M3에서 시험을 위해 만든 플랜 · 한도 강제 설정(개발용 플래그나 시험 계정 우회)이 있으면 이 단위에서 제거하고, 운영 코드에 남지 않았음을 `grep` 결과로 보고한다. 서버의 권한 판정은 `entitlements`만 본다.
- 완료 기준: 상태별 허용/거부 표 시험(ACTIVE · GRACE · EXPIRED · REVOKED × 보내기 · AI · 수정 · 취소), **개발용 플래그 코드가 제거됨**.

## 앱 단위 (F)

### F5-01 결제 어댑터 (설계도 12.1 · 13.9)
- 라이브러리는 B5-01 결정에 따른다: 직접 구현이면 `expo-iap` 계열 · `react-native-iap`, RevenueCat이면 해당 SDK. **설치 전 최신 문서로 Expo SDK 57 호환 여부를 확인**하고 이름 · 사유를 보고. 인터페이스는 `application/entitlement`에 두고(`purchase(productId)`, `restore()`, `openManage()`), 구현은 `adapters/iap`.
- 구매 후 영수증을 `iap_verify`로 보내고, **서버 검증 결과가 오기 전에는 혜택을 열지 않는다.**

### F5-02 페이월 B1 (설계도 9.2, 시안 `#planPage`)
- 진입: 체험 소진 · 한도 초과 · 무료 회원의 보내기 시도 · 설정 > 구독. 진입 이유가 문구로 보인다(시안 `PLAN_REASONS`: `ai`, `sendExpense` 등).
- 내용: 두 플랜 카드(가격 · **한도 숫자** · 포함 기능), 현재 플랜 표시, [구독하기], [구매 복원], **자동 갱신 안내 문구**, 이용약관 · 개인정보 처리방침 링크, **해지 방법 안내**(스토어 구독 관리).
- **확인 필요:** 애플 · 구글의 자동 갱신 구독 필수 고지 문구와 표시 위치 — 최신 심사 지침으로 확인한 뒤 문구를 확정한다(M6 체크리스트에 재확인).
- 게스트가 구독을 누르면 먼저 로그인 안내.

### F5-03 구매 상태 화면 (설계도 15, 시안 `purchaseView`)
| 상태 | 화면 · 동작 |
| --- | --- |
| 구매 성공 + 서버 검증 실패/지연 | **"구매 확인 중이에요"** 표시, 자동 재시도, [구매 복원] 안내. 이 상태에서는 혜택을 열지 않는다. 스토어 웹훅으로도 반영됨 |
| 자동 재확인 성공 | 확인 중 해제, 구독 중 표시 |
| 결제 유예(`GRACE`) | 혜택 유지 + "결제 확인이 필요해요. 유예 기간 동안은 구독 혜택이 그대로 유지돼요" 안내(스토어 결제 수단 확인 유도) |
| [구매 복원] 결과 | 성공 "구독을 복원했어요" / 없음 "복원할 구독을 찾지 못했어요" / 다른 계정 "다른 계정에서 사용 중인 구독이에요" |
| 환불 · 해지 | 서버가 `entitlements` 갱신 → 다음 `sync`에서 앱 반영(해지는 기간 끝까지 유지) |
- 설정 > 구독 구역: 현재 플랜, 이번 달 / 오늘 AI 사용량, 체험 남은 횟수, [플랜 보기], [구매 복원], [스토어에서 구독 관리](스토어 구독 관리 화면 열기). 요금제 값에 "구매 확인 중" · "결제 확인 필요"가 보일 수 있다.
- 시험: 위 5가지 상태 전이(가짜 어댑터로), 확인 중에 AI/보내기가 열리지 않음.

### F5-04 만료 처리 · 게이트 표시 (설계도 9.3)
- 만료되면 새 보내기 · 지출 보내기 · AI(체험 외)가 막히고, 막힌 버튼은 비활성이 아니라 **이유 + [구독 보기]** 를 보인다. 이미 보낸 항목의 수정 · 취소는 가능.
- 서버가 판정하므로 앱은 `NOT_ENTITLED` · `DAILY_LIMIT` · AI 한도 응답을 문구로 옮기는 역할만 한다. 앱 쪽 캐시로 혜택을 미리 열지 않는다.
- 시험: 만료 상태에서 보낸 항목 수정 · 취소 가능, 새 보내기 불가, 체험 남아 있으면 AI/공유 체험 사용 가능.

### F5-05 사용량 · 플랜 캐시 갱신
- 앱 시작 · 포그라운드 전환 · `PLAN_CHANGED`(`sync`) · 구매 직후에 `get_entitlement`로 갱신한다.
- 오프라인이면 마지막으로 받은 값을 **표시용으로만** 보여 주고, 앱은 이 값으로 기능을 열거나 막지 않는다(허용 판단은 서버). 표시에 "마지막 확인 시각"을 붙인다.

## M5 시험 목록 요약
- 서버: 영수증 검증(정상 · 위조 · 다른 계정) · 웹훅 서명 검증 · 웹훅 멱등 · 갱신 · 해지 · 환불 · 유예 · 업그레이드 사용량 이전 · 상태별 게이트 표.
- 앱: 구매 상태 전이 5종 · 확인 중 혜택 없음 · 만료 게이트 · 복원 3결과.
- **샌드박스 실기기:** 구매 → 갱신 → 해지 → 환불 → 복원, 기본 → 플러스 업그레이드(애플 샌드박스 · 구글 테스트 트랙 라이선스 테스터).
