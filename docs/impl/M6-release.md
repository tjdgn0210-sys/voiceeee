# M6 출시 준비

설계도 18장: "17장 요건, 개인정보 처리방침 · 약관, 스토어 자료, 비공개 테스트, 성능 · 접근성 점검". 담당: 전원. **완료 기준: 제출 체크리스트 완료.**

설계도 17장은 작성 시점의 **일반적 요건**이다. **제출 전에 Apple App Store 심사 지침과 Google Play 정책의 최신판으로 반드시 다시 확인**하고, 확인 날짜와 결과를 `docs/impl/m6-store-check.md`에 적는다. 이 문서의 어떤 항목도 최신 정책 확인 없이 "충족"이라고 쓰지 않는다.

선행: M1 ~ M5 완료. 단, **Google Play 비공개 테스트와 개발자 계정은 M6가 아니라 M0에서 시작**해야 한다(신규 개인 계정 요건이 있을 수 있음).

## 작업 단위

### M6-02 개인정보 처리방침 · 이용약관 · 데이터 표 (설계도 16.1 · 20.1)
- 16.1 표의 항목(소셜 로그인 식별자 · 닉네임 · 프로필 사진 · 일정 · 지출 · 할 일 백업 · 공개 일정 사본 · 보낸 항목 · 전달 기록 · 푸시 토큰 · 기기 정보 · 구독 거래 정보 · AI 요청 지문 · 신고 내용)을 목적 · 보관 · 삭제 시점과 함께 방침에 기재한다.
- 반드시 포함: **AI 해석 시 문장이 OpenAI(미국)로 전송된다는 처리 위탁 · 국외 이전 고지**, 음성 원본은 어디에도 저장하지 않음, Supabase 데이터 저장 지역(서울 리전 확인 결과, M0-02).
- 법률 검토 권장(만 14세 확인 방식이 법적 확인 의무를 충족하는지, 국외 이전 고지, 거래 기록 보관 기간, 사업자 등록 · 통신판매업 신고 필요 여부).
- 페이지 게시 위치: M0-03 도메인. 앱 안의 링크(로그인 화면 · 페이월 · 설정 > 정보)와 스토어 등록 정보가 같은 주소를 가리켜야 한다.

### M6-03 권한 문구 · 앱 설정 (`app.json`)
- iOS: 마이크, 음성 인식, 사진 보관함, 카메라, 알림 — 사용 목적을 한국어로 구체적으로(예: "말씀하신 문장을 글자로 바꿔 일정과 지출을 기록하기 위해 마이크를 사용해요. 녹음은 저장하지 않아요").
- Android: `POST_NOTIFICATIONS`, 정확한 알람(`SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM`) — **정책 최신 확인 후** 어느 권한을 쓸지 확정하고 사용 근거를 신청서에 적는다. 필요 없는 권한은 제거.
- 앱 이름 · 번들 ID · 패키지명 · 버전 · 아이콘 · 스플래시 · 딥링크 스킴 · 연결 도메인(M0-04 결정)을 최종 점검.

### M6-04 스토어 등록 자료 (설계도 20.1)
- 앱 이름 · 아이콘 · 스크린샷(시안이 아니라 **실제 앱 화면**, 글자 크기 100%) · 설명 · 키워드 · 지원 이메일 · 개인정보 URL.
- 설명 문구 규칙: **"무제한"을 쓰지 않는다. 한도는 숫자로**(기본 AI 월 150회 · 하루 20회, 플러스 월 500회 · 하루 40회, 보내기 하루 50건). 스토어 설명과 실제 한도가 다르면 심사 · 민원 위험이 있다(1.3).
- 한국어 전용임을 명시. 애플 · 구글에서 요구하는 구독 정보 입력(상품 이름 · 가격 · 기간).

### M6-05 심사용 계정 · 심사 메모 (설계도 17장)
- 시험용 계정 **2개**를 만들고 **서로 친구 상태**로 둔다(링크로 연결). 한 계정은 구독 상태(샌드박스), 다른 계정은 무료 회원으로 두면 보내기 · 받기 · 체험 · 페이월을 모두 시험할 수 있다.
- 심사 메모(한국어 + 영어): 로그인 방법(애플 · 구글 · 카카오 중 심사에서 쓸 수 있는 방법), 시험 계정 안내, 주요 흐름(AI 문장 · 보내기 · 받기), 샌드박스 구독 시험 방법, 신고 · 차단 · 계정 삭제 위치, 음성 인식 권한이 필요한 위치, **로그인이 필요한 기능은 게스트로 시작해도 앱 사용이 가능**함을 명시.
- 개인정보에 해당하는 실제 계정 정보는 저장소 · 문서에 쓰지 않는다(스토어 심사 정보 입력란에만).

### M6-06 비공개 테스트 · 베타 (설계도 17장, 20.1)
- Android: 비공개 테스트(인원 · 기간 요건 확인) 트랙에 빌드를 올려 실사용자 시험. iOS: TestFlight.
- 시험 시나리오(최소): 설치 → 게스트 → 일정 · 지출 입력 → 알림 울림 → 로그인 → 백업 → 앱 삭제 → 재설치 → 복원 → 친구 연결 → 보내기 → 받기 → 수정 · 취소 → 구독(샌드박스) → 탈퇴.
- 수집: 충돌 · 알림 미도착 · 문구 오류. 실제 AI 사용량을 측정해 **한도 재조정 필요 여부**를 판단(설계도 9.5 · 20.2, 한도는 서버 설정값이므로 앱 업데이트 없이 조정 가능).

### M6-07 성능 · 접근성 점검 (설계도 12.6, 10.2)
- 접근성: 모든 버튼에 VoiceOver / TalkBack 이름, 터치 영역 44px 이상, 색만으로 상태를 구분하지 않음, **200% 글자에서 모든 화면 사용 가능**, 70 · 100 · 130 · 200% 캡처 비교(M1-16 이어서 전체 화면).
- 성능: 콜드 스타트 시간, 캘린더 월 이동 · 목록 스크롤(1년치 일정 · 지출 데이터로), 백업 업로드 · 복원 시간(수천 건), 배터리(알림 · 동기화 빈도). 측정값을 기록하고 기준(체감 지연 · 프레임 드롭)을 넘는 곳을 목록으로 보고.
- 오프라인 시나리오 전수: 오프라인에서 AI 문장 · 보내기 · 취소 · 연결 해제 · 차단 · 초기화 · 탈퇴 · 엑셀이 설계도 15장 표대로 동작.

### M6-08 보안 · 출시 전 최종 점검 (설계도 16.2 · 20.2)
- 16.2 체크리스트: 앱에 공개 키(anon)만 · 모든 테이블 RLS · 입력 검증 서버 재검사 · 토큰 해시 저장 · 요청 제한(닉네임 검색 · 링크 생성 · 보내기 · AI · 신고) · 로그에 개인 내용 없음 · 엑셀 수식 주입 방지 · 프로필 사진 EXIF 제거 · 웹훅 서명 검증. 각 항목에 확인 방법과 결과를 적는다.
- 20.2 "확인 필요" 목록을 **모두 최신 공식 자료로 재확인**하고 결과를 기록: Supabase(카카오 로그인 · 다른 세션 강제 종료 · 서울 리전 · 요금 · 백업 · 일시정지), 애플(로그인 정책 · 계정 삭제 · 사용자 콘텐츠 · 자동 갱신 고지 · 소규모 사업자 수수료 · 로컬 알림 64개 · 개발자 계정), 구글(정확한 알람 · 알림 권한 · 데이터 보안 양식 · 웹 계정 삭제 · 비공개 테스트 · 수수료), 법령(만 14세 확인 · 국외 이전 고지 · 거래 기록 보관 · 사업자 등록 · 통신판매업), 비용(OpenAI 단가 · 환율 · 실제 토큰 사용량), 결제 서비스 비용(RevenueCat 선택 시).
- 비밀 값 점검: 저장소 이력과 앱 번들에 키 · 토큰이 없다(`git log -p`/문자열 검색 결과 보고).

### M6-09 빌드 · 제출 (설계도 2.3 — EAS Build / EAS Submit)
- 운영용 환경 변수(운영 Supabase URL · anon 키 · 게이트웨이 주소)로 프로덕션 빌드. 버전 · 빌드 번호 규칙 정하기.
- iOS(TestFlight → 심사) · Android(비공개 테스트 → 프로덕션). **제출 버튼은 앱 소유자가 누른다.** 거절 시 사유와 대응을 기록.
- 출시 후: 크래시 · 푸시 실패율 · PENDING 전달 수 · AI 호출 수와 비용 지표(13.10)를 매일 확인하는 방법 정리.
