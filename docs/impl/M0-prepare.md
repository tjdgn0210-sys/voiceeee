## 작업 단위

### M0-01 규칙 개정 · 시안 · 문서 커밋 (Claude Code, 앱 소유자 승인 후)
- 할 일: `AGENTS.md`, `CLAUDE.md`, `docs/`(설계도 PDF · 이 명세서), `design/` 변경분을 **한 번에 하나씩 의미 있는 단위로** 커밋한다. 커밋 · 푸시는 앱 소유자가 요청할 때만 한다.
- 확인: `git diff --stat`로 변경 파일을 보여 주고, `AGENTS.md`에 옛 범위 규칙이 남아 있지 않은지 `grep`으로 확인한다. 키워드는 영어 · 한국어 둘 다 쓴다(예: `cloud sync`, `recurring`, `repeat`, `no account`, `login`, `friend`, `share`, `클라우드`, `반복`, `로그인`, `친구`, `공유`). 설계도 18장 범위 목록 19번(반복 일정)은 1차 제외 항목이므로 "반복 일정 금지"는 **남아 있어야 정상**이다. 나머지 금지 문구가 남아 있으면 보고한다.
- 기술 규칙(UTC 저장, 양의 정수 금액, 되돌리기, 멱등성, 실패를 성공으로 보고하지 않기, 계층 의존 방향)은 **유지**되어 있어야 한다.
- **`CLAUDE.md` 수정 허용 범위 점검:** 현재 규칙이 `eas.json`(M2 개발 빌드 · M6 빌드), `supabase/`(M0-02 이후 마이그레이션 · 함수), `server/`, 시험 파일 위치(M0-06에서 정한 곳), `app.json`(M6-03)을 수정 가능 범위에 포함하는지 확인하고, 빠진 것은 앱 소유자 승인 후 추가한다. 포함되지 않은 채로 M2 이후를 시작하면 허가 없는 파일 수정이 된다.
- 완료 기준: 커밋 해시와 변경 파일 목록을 보고.

### M0-02 Supabase 프로젝트 (백엔드 · 앱 소유자)
- 프로젝트 생성. **리전은 가능하면 서울(ap-northeast-2)**. 서울이 없거나 요금제 제약이 있으면 사유를 기록하고 앱 소유자가 결정한다(개인정보 국외 이전 고지에 영향, 설계도 16.1).
- 확인 필요 항목을 공식 문서로 확인하고 결과를 `docs/impl/m0-checks.md`에 날짜와 함께 적는다:
  1. 카카오 로그인 지원 방식(Supabase Auth 기본 제공자인지, 커스텀 OIDC로 붙여야 하는지)과 닉네임 · 고유 ID만 받는 설정(이메일 수집 없음).
  2. 다른 세션 강제 종료 방법(1계정 1기기, 설계도 13.1).
  3. 요금제(Pro 가정 월 약 $25), 자동 백업 정책, 무료 플랜 일시정지 정책.
- 저장소 폴더 제안: 저장소 루트의 `supabase/`(`migrations/`, `functions/`, `config.toml`). 현재 `server/`는 AI 게이트웨이(Node)이므로 그대로 둔다. AI 게이트웨이를 Edge Function으로 옮길지(14.3 B) 그대로 둘지(A)는 M3에서 백엔드 담당이 결정한다.
- 비밀 값: OpenAI 키 · 서비스 역할 키 · 스토어 키는 서버 비밀 저장소에만 둔다. 앱에는 공개(anon) 키만 넣는다. `.env.example`에 이름만 적는다.
- 완료 기준: 프로젝트 URL과 anon 키가 앱 소유자에게 전달되고(문서에는 쓰지 않음), 로컬에서 `supabase` CLI로 마이그레이션을 적용해 볼 수 있다.

### M0-03 도메인과 웹페이지 (앱 소유자)
도메인 1개와 간단한 정적 웹페이지가 필요하다(설계도 5.1 · 17 · 20.1).
- 초대 링크: `https://<도메인>/i/<토큰>` — 앱이 없는 사람에게는 소개 페이지에서 스토어로 안내.
- 연결 파일: iOS `/.well-known/apple-app-site-association`, Android `/.well-known/assetlinks.json`. 내용은 앱 번들 ID · 패키지명 · 서명 지문이 정해진 뒤 작성한다(M0-04의 앱 식별자 확정이 먼저).
- 정책 페이지: 개인정보 처리방침, 이용약관, 웹 계정 삭제 요청 양식(구글 Play 요구), 문의 이메일.
- 법률 검토 권장: 개인정보 처리방침 · 약관 · 만 14세 확인 방식(설계도 16.1, 3.7, 20.2).
- 완료 기준: 위 주소가 HTTPS로 열리고, 연결 파일이 올바른 `Content-Type`으로 내려간다.

### M0-06 저장소 기준선 확인 (Claude Code)
- `pnpm install` → `pnpm typecheck` → `pnpm lint` → `pnpm test`를 실행해 **현재 통과 여부와 시험 개수**를 기록한다(M1 이후 회귀 비교 기준). 실행하지 못하면 이유를 보고한다.
- **시험 실행기와 시험 파일 위치를 기록한다**(어떤 러너인지, `*.test.ts`가 어디에 있는지, `server/`의 시험 명령). 이후 마일스톤의 "시험" 항목이 이 위치 · 방식을 따른다. 위치가 `CLAUDE.md`의 수정 허용 범위 밖이면 M0-01의 점검 항목으로 올린다.
- `pnpm web`(또는 `npx expo start --web`)으로 현재 지출 화면이 뜨는지 확인한다. 포트 8081 · 8082를 쓰는 다른 프로세스가 있는지 먼저 본다.
- 옛 복제본 폴더(`C:\voice-good\voice-good-main` 등 `C:\dev\voice-good` 밖의 사본)를 정리 대상으로 목록만 보고한다. 삭제는 앱 소유자가 확인한 뒤.
