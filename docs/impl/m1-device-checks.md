# M1 실기기 확인 목록

M1 구현(M1-04 ~ M1-16)은 코드 · 자동 시험 · 웹 미리보기까지만 확인했다. 아래는 **실기기(iOS · Android)에서만 확인할 수 있는 항목**이다. 확인하기 전에는 "동작함"이라고 쓰지 않는다(`AGENTS.md` 18).

작성일: 2026-10-04

## 1. 알림 (M1-08)

개발 빌드가 필요하다(Expo Go 불가가 아니라면 `npx expo run:android|ios` 또는 `eas build --profile development`).

- [ ] 새 일정(정시 알림)을 몇 분 뒤로 만들면 그 시각에 알림이 울린다 — iOS · Android 각각
- [ ] 10분 전 알림이 울린다(문구 `병원 예약 · 10분 후 (장소)`)
- [ ] 앱을 완전히 종료한 뒤에도 울린다
- [ ] 기기를 재부팅한 뒤에도 남아 있다(앱을 한 번 열기 전에는 울리는지, 열면 다시 채워지는지)
- [ ] 배터리 절약 모드에서도 울린다(Android는 늦게 울리면 정확한 알람 권한 문제 — 아래 4번)
- [ ] 설정 > 알림 > "잠금 화면에 제목 보이기"를 끄면 `일정 알림 · 30분 후`로만 보인다
- [ ] 권한을 거부하면 일정 상세에 "알림 꺼짐"과 [설정 열기]가 보이고, 설정에서 켠 뒤 앱으로 돌아오면 알림이 예약된다
- [ ] iOS: 64개 한도 — 일정 70개쯤(각각 알림)을 만든 뒤 앞쪽 64개만 울리고, 앱을 열 때 나머지가 채워진다
- [ ] 일정 시각을 바꾸면 이전 시각에는 울리지 않고 새 시각에 울린다. 일정을 지우면 울리지 않고, [되돌리기]하면 다시 울린다
- [ ] Android 13+: 처음 알림 허용 팝업이 나온다

## 2. 글자 크기 (M1-12)

- [ ] 70 · 100 · 130 · 200% 각각에서 홈 · 캘린더 · 지출 · 사람 · 설정 · 일정 입력 · 일정 상세 · 엑셀 · 글자 크기 화면이 잘리지 않고 가로 스크롤이 없다(웹 375px 폭에서는 확인함)
- [ ] 슬라이더를 손가락으로 끌면 단계가 바뀐다(드래그), [−] [+]도 동작한다
- [ ] "시스템 글자 크기 따르기"를 켜고 기기 설정의 글자 크기를 바꾸면 앱이 따라간다(앱으로 돌아올 때 반영)
- [ ] 상단 헤더가 큰 글자에서 답답하지 않다(헤더 높이는 시스템 기본)
- [ ] 키보드가 입력창을 가리지 않는다, 노치 · 홈 인디케이터와 탭 바가 겹치지 않는다

## 3. 음성 · 파일 · 선택기 (M1-04 · M1-11 · M1-13)

- [ ] 음성 버튼: 마이크 권한 팝업 → 말하면 로컬 파서 결과가 **바로 저장**되고 화면 아래 [되돌리기] 바가 약 8초 보인다
- [ ] 같은 문장을 3분 안에 다시 말하면 "같은 기록이 방금 있어요"가 나온다
- [ ] 날짜 · 시간 선택기(iOS 인라인 / Android 대화상자)로 일정 날짜와 시각을 고를 수 있다
- [ ] 엑셀: 설정 > 내 데이터 > 엑셀로 내보내기 → 공유 시트가 열리고 저장 · 전송이 된다. 열어 보면 한글이 깨지지 않고, `=1+1`로 시작하는 메모가 수식으로 계산되지 않는다(Excel · Numbers · Google 스프레드시트)

## 4. Android 정확한 알람 정책 (확인 필요, M6 사유 기재)

- 공식 문서(developer.android.com, alarms/schedule)는 `USE_EXACT_ALARM`을 "알람 시계 · 캘린더 앱처럼 핵심 기능이 정확한 알람인 앱"에 허용한다고 하고, Google Play 정책은 "예정"이라고만 적혀 있다.
- 지금 앱은 두 권한을 **선언하지 않았다**. `expo-notifications`는 정확한 알람이 불가하면 정확하지 않은 예약으로 대신한다.
- 결정할 것: 출시 전에 Play 정책 문서를 다시 확인하고 `USE_EXACT_ALARM`을 선언할지(캘린더 앱으로 신청) 정한다.

## 5. 화면 읽기 프로그램 (M1-16)

VoiceOver(iOS) · TalkBack(Android)로 **홈 → 일정 입력 → 캘린더 → 알림 설정** 흐름을 한 번 훑고 아래를 확인한다.

- [ ] 모든 버튼의 이름이 읽히고 역할(버튼 · 스위치 · 탭)이 맞게 읽힌다
- [ ] 탭 바에서 "캘린더, 선택됨"으로 읽힌다
- [ ] 캘린더 날짜가 "10월 4일 (일) 오늘, 일정 1개"로 읽히고 선택 상태가 읽힌다
- [ ] 글자 크기 슬라이더가 "조절 가능"으로 읽히고 위 · 아래 쓸기로 한 단계씩 바뀐다
- [ ] 기본 알림(없음 · 정시 ...) 선택은 체크 상자 역할로 읽힌다(한 개만 고르는 값이라 라디오가 더 맞을 수 있음 — 확인 후 결정)
- [ ] 오류 문구가 입력 칸 아래에서 바로 읽힌다
- [ ] 되돌리기 바가 나타날 때 문구가 읽힌다

### 지금까지 찾은 이름 · 읽기 순서 문제 (코드 검토, `scripts/verify-accessibility.cjs`)

1. 웹(react-native-web 0.21)은 `accessibilityState`를 `aria-*`로 바꿔 주지 않아 선택 상태 컨트롤에 `aria-selected` · `aria-checked`를 함께 달았다. **그 밖의 컨트롤(비활성 · 처리 중 상태 등)은 웹에서 상태가 읽히지 않는다** — 모바일이 목표이므로 두었다.
2. (고침) 일정 상세에서 화면 제목 "일정"과 카드의 "일정" 작은 제목이 연달아 읽히던 중복을 없앴다.
3. 기본 알림 선택이 다중 선택용 체크 상자 역할을 쓴다(위 확인 항목).
4. 상단 헤더 제목 · 높이는 시스템 기본이다(제목 글자만 배율을 따른다).

## 6. 자동 · 웹으로 확인한 것 (참고)

- 웹 미리보기(375px 폭)에서 70 · 100 · 130 · 200% 각각, 홈 · 캘린더 · 지출 · 사람 · 설정 · 글자 크기 · 엑셀 · 라이선스 · 일정 입력 · 할 일 입력 · 지출 직접 입력 · AI 연결 12개 화면에 가로 넘침과 잘린 글자가 없었다(스크립트로 측정). 200%에서 일정 상세도 확인했다.
- 화면별 캡처 비교는 실기기에서 남긴다(이 환경은 화면을 파일로 저장하지 못했다).
